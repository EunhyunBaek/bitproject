1. 오류 수정 (Bug Fixes & Debugging)
--------------------------------------------------------------------------------

[수행 항목 1.1] 프론트엔드-백엔드 API 경로 미일치 (404 Not Found)
- 사용 프롬프트:
  "프론트엔드에서 로그인 요청을 보낼 때 404 에러가 발생해. App.jsx의 API_BASE 경로와 server.js의 Express 라우터 설정 경로를 확인하고 맞춰줘."
- 해결 및 적용 내용:
  - 프론트엔드가 `/login`으로 요청하던 주소를 백엔드 라우터 규칙인 `/api/login`으로 통일.
  - `client/src/App.jsx` 내 `API_BASE`를 `https://bitproject-srz0.onrender.com/api`로 수정하여 연결 성공.

[수행 항목 1.2] 보안 감사 로그 접속 IP의 IPv6 루프백(`::1`) 표기 문제
- 사용 프롬프트:
  "Render 배포 환경에서 감사 로그의 접속 IP가 실제 IP가 아닌 '::1'로만 표기되고 있어. Express의 trust proxy 설정과 IP 정제 함수, 그리고 기존 DB 데이터 일괄 보정 쿼리까지 적용된 server.js 전체 코드를 작성해줘."
- 해결 및 적용 내용:
  - `app.set('trust proxy', true);` 구문 적용.
  - `getClientIp` 유틸리티 함수를 구현하여 `cf-connecting-ip`, `x-forwarded-for` 등의 프록시 헤더 파싱 및 IPv6(`::1`, `::ffff:`) 정제 처리.
  - DB 초기화 단계에서 기존 `::1` 기록을 `127.0.0.1`로 변환하는 SQL 쿼리 추가.

[수행 항목 1.3] README.md 마크다운 실행 방법 깨짐 현상
- 사용 프롬프트:
  "README.md의 실행 방법 섹션에서 코드 블록이 일반 텍스트처럼 한 줄로 깨져서 나와. VS Code 터미널 상자처럼 출력되도록 마크다운 문법을 개선해줘."
- 해결 및 적용 내용:
  - 기존 수평선(`---`) 태그를 백틱 3개(` ```bash `) 코드 블록 문법으로 교체하여 가독성 확보.

2. 진행 방향 질문 및 아키텍처 검토 (Architecture & Direction Clarifications)
--------------------------------------------------------------------------------

[수행 항목 2.1] InterviewTasks.txt 과제 요구사항 분석 및 구현 스펙 수립
- 사용 프롬프트:
  "InterviewTasks.txt 명세서의 보안, 백엔드 연동, 감사 로그 및 백그라운드 체크 과제 요구사항을 분석해서 Express 서버에 필수적으로 구현해야 할 핵심 기능 목록을 정리해줘."
- 논의 및 적용 내용:
  - JWT 토큰 인증, 퇴사자 실시간 접근 차단, 비밀번호 정책 검증, 503 에러 지연 재시도(Exponential Backoff), SSE 알림 요구사항 추출 및 설계 반영.

[수행 항목 2.2] swagger.yaml 명세 기반의 API 엔드포인트 및 스키마 검토
- 사용 프롬프트:
  "제공된 swagger.yaml 명세서의 HTTP 메서드, Request Body, Response 스키마와 일치하도록 백엔드 라우터 구조 및 데이터 모델을 검토해줘."
- 논의 및 적용 내용:
  - `/background-checks` 관련 POST/GET 엔드포인트의 입력 파라미터(`employeeId`, `firstName`, `lastName`, `dateOfBirth`) 및 응답 구조 정합성 검증.

[수행 항목 2.3] 배포 환경 내 프록시 및 클라이언트 실제 IP 수집 구조 검토
- 사용 프롬프트:
  "Vercel(프론트엔드)과 Render(백엔드)가 분리된 환경에서 클라이언트의 실제 IP를 데이터베이스에 안전하게 기록하려면 어떤 방식으로 정제해야 하는지 방향을 제시해줘."
- 논의 및 적용 내용:
  - Express 신뢰 설정(`trust proxy`) 검토 및 Cloudflare, Render 로드밸런서 환경에 대응하는 IP 파싱 가이드라인 수립.

3. 기능 추가 및 코드 개선 (Features & Improvements)
--------------------------------------------------------------------------------

[수행 항목 3.1] Express 웹 서버 보안 미들웨어 및 Rate Limiting 구축
- 사용 프롬프트:
  "InterviewTasks.txt의 보안 요구사항에 따라 Helmet, CORS, 그리고 로그인 15분당 10회 제한을 위한 Rate Limiting 미들웨어를 server.js에 추가해줘."
- 개발 및 적용 내용:
  - `helmet()`, `cors()`, `express-rate-limit` 모듈 적용 및 JSON 페이로드 크기 제한(10kb) 설정.

[수행 항목 3.2] SQLite3 데이터베이스 및 JWT/bcrypt 기반 인증 구현
- 사용 프롬프트:
  "users 및 audit_logs 테이블을 생성하고, bcrypt 비밀번호 암호화와 JWT 토큰 기반의 로그인 및 프로필 관리 API를 swagger.yaml 명세에 맞게 작성해줘."
- 개발 및 적용 내용:
  - `users`, `audit_logs` 테이블 자동 생성 및 초기 테스트 계정 생성.
  - JWT 발급 및 실시간 퇴사자 접근 차단 미들웨어(`authenticateToken`) 구현.

[수행 항목 3.3] 보안 감사 로그 (Audit Log) 및 SSE 실시간 알림 구현
- 사용 프롬프트:
  "모든 작업(로그인, 직원 생성, 퇴사 처리 등) 수행 시 접속 IP와 수행 결과를 audit_logs에 남기고, 백그라운드 체크 진행 상태를 프론트엔드로 브로드캐스트하는 SSE 엔드포인트를 구현해줘."
- 개발 및 적용 내용:
  - `logAudit` 유틸리티를 통한 IP 정제 후 DB 저장.
  - `/api/events` SSE 스트림 연결 및 `sendSseEvent` 브로드캐스트 로직 구축.

[수행 항목 3.4] swagger.yaml 명세 준수 외부 Background Check API 연동
- 사용 프롬프트:
  "swagger.yaml의 Background Check API 연동 규격을 준수하고, 503 Service Unavailable 발생 시 지연 재시도(Exponential Backoff)가 동작하는 연동 코드를 작성해줘."
- 개발 및 적용 내용:
  - 한글 성명을 `firstName`, `lastName`으로 분리하는 `parseKoreanName` 함수 구현.
  - 503/500 에러 발생 시 Retry-After 헤더 값을 수용하여 최대 3회 재시도하는 `callExternalApiWithRetry` 비동기 함수 구현.
